# UI/UX 디자인 기준

이 메이커의 중심은 목록에서 항목을 고르고, 효과를 만들고, 미리보기로 확인하는 작업이다. 화면은 이 흐름을 유지하면서 프로젝트 상태와 작업 결과를 구분한다.

## 색상과 글자

- 흰색 편집 영역과 옅은 회청색 바탕으로 영역을 구분한다.
- 파란색은 주요 실행과 선택 상태, 붉은색은 삭제, 초록색은 저장 상태에 사용한다. 상태에는 색상과 함께 글자를 표시한다.
- 제목, 영역 이름, 입력 라벨, 보조 안내의 크기와 대비를 구분한다.
- 블록 종류별 색상은 유지하되 흰 글자와의 대비가 4.5:1 이상이 되도록 조절한다.
- 기본 값은 uxkit.py의 C와 apply_theme에서 관리한다.

## 화면 구성

- 상단: 프로젝트 이름, 저장 상태, 전체 검색.
- 도구 막대: 저장과 되돌리기, 검사 → 생성 → 빌드 → 게시. 좁은 화면의 보조 작업은 더보기에서 제공한다.
- 작업 영역: 목록 / 편집 / 미리보기. 동일한 제목 막대로 분리와 결합을 제공한다.
- 하단: 실행 기록과 작업 상태. 실행 기록은 작업 화면을 과도하게 차지하지 않도록 기본 높이를 줄인다.
- 모드 / 빌드 화면은 모드 정보, 제작 환경, 준비 상태, 게임 적용 순서로 나눈다. 단계별 실행 버튼을 설명 바로 옆에 둔다.

## 항목 편집

- 이름과 ID 열을 구분하고 현재 편집 중인 이름을 표시한다.
- 넓은 편집 영역은 두 쌍의 입력칸, 보통 폭에서는 한 쌍, 아주 좁은 폭에서는 라벨 아래 입력칸으로 배치한다.
- 키워드와 보조 버튼은 줄바꿈한다. 넓은 효과 표는 표 안에서 가로로 스크롤한다.
- 화면 구성 메뉴의 편집에 집중으로 목록과 미리보기를 접고, 같은 메뉴에서 복구한다.
- 재배치는 위젯과 입력 값을 재사용하며 숨겨진 필드를 임의로 다시 표시하지 않는다.

## 블록 편집

- 개별 블록과 저장한 묶음은 선택 상태가 분명한 전환 버튼을 사용한다.
- 검색을 도구보다 먼저 배치한다. 즐겨찾기는 목록 위에 유지한다.
- 라이브러리와 작업 공간의 바탕을 구분하고, 효과 적용을 주요 버튼으로 표시한다.
- 자주 쓰는 조작은 하단 한 줄에 두고, 원본 효과 관련 보조 조작은 메뉴에 묶는다.
- 설명과 C# 코드는 기존 보기 메뉴에서 별도 창으로 연다.

## 유지할 동작

탭과 패널의 드래그 정렬, 분리와 결합, 창 닫기로 복구, 보기 메뉴, 즐겨찾기 저장 순서, 키보드 단축키와 기존 프로젝트 형식을 유지한다. 목록 갱신과 화면 재배치는 기존의 깜빡임 방지 방식을 사용한다.


## 스크롤과 화면 재사용

- 스크롤 영역의 입력칸과 Canvas에 들어간 화면은 한 번 만들고 유지한다.
- 스크롤할 때는 Canvas 표시 위치와 스크롤바만 갱신한다. 강제로 Expose를 보내거나 Windows 하위 창을 모두 다시 그리지 않는다.
- 위젯이 들어 있는 Canvas는 휠·스크롤바로 움직인 직후, Windows가 이미 무효화한 새로 드러난 줄만 같은 처리 안에서 그린다 (uxkit.present_scroll / scroll_command). 그래야 옛 화면 조각이 잠깐 보이지 않는다.
- 설정 값이 같으면 configure 하지 않는다 (uxkit._set_if). Tk는 같은 값이어도 재배치와 다시 그리기를 한다.
- 위치만 바뀐 Configure는 재배치하지 않는다. 내용이나 영역의 크기가 바뀔 때만 재배치한다.
- 배율 변경은 기존 테마와 화면을 유지하고 글꼴, 행 높이, 미리보기 크기를 갱신한다. 아이콘은 캐시를 재사용하고 필요한 경우만 목록에 반영한다.
