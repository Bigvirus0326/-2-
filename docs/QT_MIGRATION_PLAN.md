# Tk → Qt(PySide6) 이전 계획

## 현재 상태 (이 계획을 세울 때 기준)

- Tk 앱은 그대로 실행된다. 이전 작업은 새 파일로만 진행했고, 기존 Tk 파일은 건드리지 않았다.
- 이미 옮긴 것 (모두 새 파일, 테스트 통과):
  - `qtkit.py`: 테마·색, 스크롤 페이지, 탭 묶음, `DockWorkspace`(QDockWidget 기반 탭 끌기·분리·숨기기·배치 저장)
  - `modtab_qt.py`: 모드 / 빌드 탭의 입력 칸과 준비 상태 (단계 버튼은 콜백)
  - `gallery_qt.py`: 도감 탭의 필터·크기·칸 배치·클릭 (칸 그림은 아직 자리 표시)
  - `preview_qt.py`: 카드·유물·물약·파워·캐릭터 미리보기 그리기 (전부)
- 성능 근거: 10개 탭 시험에서 Qt 탭 전환 9~32ms, Tk 실제 앱 25~85ms (보이는 창 기준). 위젯 구성이 완전히 같지 않으므로 1단계에서 실제 화면으로 다시 잰다.
- 아직 Tk인 것: 메인 창·메뉴·프로젝트 입출력(`sts2_mod_maker.py` UI 약 700줄), 블록 편집기(`blockui.py` 약 2,700줄), 이펙트·버튼 탭(`fxui.py` 약 1,500줄), 나머지 탭, 대화상자, 직접 만든 도킹(`uxkit.py`), Tk 테스트 3개.

## 원칙

1. **Tk 앱은 패리티가 확인될 때까지 계속 출시한다.** Qt 앱은 `app_qt.py`처럼 별도 진입점으로 둔다.
2. **단계마다 실행 가능 상태를 유지한다.** 한 단계가 끝나면 Qt 앱이 그 단계까지 쓸 수 있어야 한다.
3. **데이터는 바꾸지 않는다.** 프로젝트 JSON 형식과 `modgen` 생성 결과는 Tk와 같아야 한다. 단계마다 같은 조작을 두 앱에서 해서 JSON이 같은지 비교한다.
4. **로직과 화면을 나눈다.** 입력 값 → 프로젝트 dict 변환, 검사, 생성은 화면과 무관하게 두고 Qt 화면은 그 위에 얹는다.

## 단계

### 0. 준비 (커밋 · 브랜치) — 완료
- 기준 커밋: `main` 65c5182 (Tk 앱 최근 작업 묶음). 작업 브랜치: `qt-migration` 29d2460 (Qt 시험판 파일).
- `requirements-optional.txt`에 `PySide6>=6.12` 추가.
- PyInstaller 6.22.3로 최소 Qt 창을 빌드했다: 실행 파일은 오프스크린에서 정상 종료, `qwindows.dll` 포함 확인. 빌드 결과 크기 123 MB (onedir).
- 지금 작업 폴더에 커밋되지 않은 변경이 49개 있다. 먼저 의미 단위로 커밋하거나 백업해서 기준점을 정한다.
- `qt-migration` 브랜치를 만든다. 큰 변경은 이 브랜치에서 한다.
- `requirements-optional.txt`에 PySide6를 추가하고, 빌드(PyInstaller)에서 Qt 플러그인이 들어가는지 확인한다.
- 종료 기준: 기준 커밋이 있고, 빈 Qt 창이 PyInstaller 빌드에서 뜬다.

### 1. Qt 앱 껍데기 — 대부분 완료
- 완료: `app_qt.py` (메뉴, 제목 수정 표시, 저장 확인, 실행 취소·다시 실행, 마지막 프로젝트 열기), `projectio.py`(설정·프로젝트 입출력 분리).
- 패리티: 같은 프로젝트를 Tk 앱과 Qt 앱에서 저장하면 파일이 바이트 단위로 같다 (21,668 bytes).
- 남음: 탭 전환을 실제 창에서 재는 일. 탭이 하나뿐이라 측정할 수 없어서 3단계(탭 여러 개)에서 한다.
- `app_qt.py`: 메인 창, 메뉴(파일·보기·도움말), 상태 표시줄, 설정 읽기·쓰기(`load_settings`/`save_settings` 재사용), 테마 적용.
- 프로젝트 열기·저장·새로 만들기, 실행 취소·다시 실행(`UX.History` 재사용), 제목의 수정 표시.
- 화면 배율(`UI_SCALES`)은 Qt의 글꼴 크기로 옮긴다.
- 종료 기준: 같은 프로젝트 파일을 Tk와 Qt에서 열고 저장했을 때 JSON이 같다. 1단계에서 Qt 탭 전환을 실제 창에서 다시 잰다.

### 2. 작업 공간 (도킹) — 대부분 완료
- 완료: 메인 창이 `DockWorkspace`이고 탭 10개가 모두 올라간다(9개는 자리 표시). 보기 메뉴에 탭 보이기·숨기기, 떨어진 탭 되돌리기, 배치 초기화가 있다. 배치는 앱 설정(`dock_layout`)에 저장되고 다음 실행 때 복원된다.
- 테스트: 무작위 조작 300단계(떼기·붙이기·숨기기·보이기·배치 저장과 복원)에서 불변 조건을 확인한다 (`tests/test_docking_qt.py`).
- 남음: 마우스로 탭을 끌어 옮기는 동작. 합성 마우스 이벤트로는 떼어지지 않아서 실제 손으로 확인해야 한다.
- 남음: 탭 전환 측정 (3단계).
- `uxkit.ScrollNotebook` 대신 `qtkit.DockWorkspace`를 메인 창에 붙인다.
- 보기 메뉴의 탭 목록, 배치 저장·복원(설정 파일에 보관), 탭 되돌리기 메뉴를 옮긴다.
- 테스트: Tk의 `test_docking_regressions.py`(577개 전환)는 Qt에서 같은 시나리오를 다시 짠다. 마우스 끌기는 `QTest`로 흉내 낸다.
- 종료 기준: 탭 10개를 끌어 옮기고, 떼고, 숨기고, 다시 저장·복원해도 오류가 없다.

### 3. 탭 (쉬운 것부터) — 진행 중
- 완료: 모드 / 빌드 탭의 ①검사 ②생성 ③빌드 ④게시 연결 (`buildrun.py`, 화면 기록 창 '실행 기록'). 도감 탭의 칸 그림을 `preview_qt`로 바꾸고 언어·강화 선택을 추가.
- 완료: 캐릭터 탭의 '내 캐릭터' 편집 (`characterqt.py`): 이름·소개(3개 언어)·색·체력·임시 외형·카드 뒷면 HSV·카드 테두리·구체 슬롯·별 카운터·그림 7칸·시작 덱·시작 유물·미리보기. Tk 와 같은 편집을 하면 캐릭터 데이터가 같다 (9개 항목 확인).
- 남음 (캐릭터): 가져온 캐릭터 고르기, 전투 모습·모션, 아키텍트 대사, 카드 테두리 편집기 버튼(지금은 목록만 있다).
- 완료 (카드·유물·물약·파워, `itemtabqt.py`): 같은 틀(`ItemTabQt`)에 종류별 칸만 다르다. 목록(찾기·새로 만들기·복제·삭제), 기본 칸, 키워드·특수 플래그, 설명 직접 입력(3개 언어, 카드는 강화 설명 포함), 그림, 추가 C# 코드, 미리보기. ID 바꾸기·삭제 때 덱·유물·다른 카드 참조를 Tk 와 같은 규칙으로 고친다. 유물의 '강화 버전 만들기'와 파워 사용 중 삭제 경고도 있다. 패리티: 같은 편집 시나리오를 Tk 와 Qt 에서 했을 때 두 쪽이 쓰는 칸이 전부 같다 (카드·유물·물약·파워 전체 기준, 차이 0).
- 완료 (효과 목록, `effectqt.py`): 효과 추가·편집·삭제·순서 바꾸기와 효과 편집 창 (종류, 수치, 강화, 타격, 파워, 대상, X 사용, 조건, 스택 비례, C# 직접 입력, 설명 문구, 강화 설명). 블록이 있는 효과는 블록이 만든 C# 과 설명을 읽기 전용으로 보여 주고 그대로 저장하며, '블록 해제'도 된다. 규칙은 `effectrules.py` 로 옮겨 Tk 와 함께 쓴다. 패리티: 같은 편집 5가지를 Tk `EffectDialog` 와 Qt `EffectDialogQt` 에서 했을 때 결과 값이 전부 같다. 테스트: `tests/test_effect_qt.py` (16개).
- 남음 (효과): 블록 편집기(블록 편집·다시 만들기), 원본 효과(통째로 가져온 카드)의 블록 다시 풀기, 카드의 강화 후 효과(따로 설정)와 뽑을·버릴·소멸할 때 효과, 파워의 상시 효과(수정자).
- 남음 (카드·유물·물약·파워): 카드 틀(`frame_style`), 카드 전용 캐릭터, 카드 종류 만들기, 기믹 태그·자원·사용 조건, 파워의 넘칠 때/기준치 블록, 끌어서 순서 바꾸기, 여러 개 한꺼번에 바꾸기.
- 남음: 도감의 '게임 화면' 그림 방식, 기믹, 이펙트·버튼, 다른 모드 탭. 탭 전환 측정은 이 탭들이 다 올라간 뒤에 한다.
- 알려진 문제: 전체 테스트를 한 프로세스에서 돌리면 Qt 테스트와 Tk 테스트가 섞여 가끔 세그폴트가 난다(`test_docking_regressions` 근처). `qtkit`·`itemtabqt` 변경 전의 `HEAD` 에서도 같은 현상이 3번 중 1번 난다. 개별 모듈은 모두 통과한다.
순서: 모드 / 빌드(폼은 완성, 단계 버튼 연결) → 도감(실제 그림 연결) → 캐릭터 → 카드·유물·물약·파워(같은 `ItemTab` 베이스로 한 번에) → 기믹 → 이펙트·버튼 → 다른 모드.
- 탭마다 종료 기준: 같은 조작을 Tk와 Qt에서 했을 때 프로젝트 JSON이 같고, 미리보기 화면이 Tk와 같은 배치다.
- 기존 Tk 탭 파일은 이 단계가 끝날 때까지 그대로 둔다.

### 4. 대화상자·보조 창
- `EffectDialog`, `ModifierDialog`, `RawVarDialog`, `ArchitectDialog`, 카드 틀 편집기(`cardframeui`), 설명 편집기(`descriptionui`), AI 안내(`aiui`), 피드백(`feedbackui`), 카드 라이브러리(`card_library`), 프로젝트 검토(`project_review`), 카드 목록 끌기(`cardlistdrag`), 그림 편집(`artui`).
- 종료 기준: 대화상자를 열고 값을 바꾸면 프로젝트 JSON에 같은 값이 들어간다.

### 5. 블록 편집기 (가장 큰 위험)
- `blockui.py`(약 2,700줄)는 별도 하위 계획으로 나눈다. 먼저 블록 데이터 모델(`blockcode`, `blockfamilies`, `csblocks` 등)과 화면을 떼어 놓는 작업부터 한다.
- 종료 기준: 기존 블록 프로젝트 여러 개를 Qt 편집기에서 열고 저장해도 생성되는 코드가 같다.

### 6. Tk 제거
- `uxkit.py`의 Tk 코드, Tk 테스트, `preview.py`의 Tk 그리기 부분을 지운다(글 해석·값 채우기는 남긴다).
- `README.md`의 빌드 안내와 `docs/UI_DESIGN.md`를 Qt 기준으로 고친다.
- 종료 기준: 모든 테스트가 Qt 기준으로 통과하고, Tk 전용 코드가 남지 않는다.

## 결정이 필요한 것

1. **Tk 앱 유지 기간:** 패리티 전까지 Tk를 계속 출시하는 것(추천)과, 중간에 바꿔 버리는 것 중에서 고른다.
2. **작업 위치:** 별도 브랜치 `qt-migration` 또는 별도 작업 폴더(git worktree)에서 하는 것(추천). 지금 폴더의 커밋되지 않은 변경과 섞이지 않게 한다.
3. **1단계 성능 기준:** 실제 화면에서 탭 전환이 목표(예: 16ms 이하)에 못 미치면, 그 전에 위젯 수를 줄일지 결정한다.

## 위험

- 블록 편집기 이전(5단계)이 일정의 대부분을 차지할 가능성이 크다.
- 글꼴: Malgun Gothic은 Windows에 있지만, 줄바꿈과 글자 폭이 Tk와 달라서 레이아웃을 다시 맞춰야 한다.
- 테스트 자산: Tk 전용 테스트 3개(docking 577 전환 포함)는 대체 테스트를 먼저 만든 뒤에 지운다.
- 패키징: PyInstaller 설정과 Qt 플러그인 포함 여부를 0단계에서 확인해야 한다.
